# lab1-faculty-sport

Інформаційна система "Спорт на факультеті" — консольний застосунок на Haskell
для обліку студентів і тренерів, які займаються у спортивних секціях, графіка
роботи секцій та плану проведення змагань. Дані зберігаються у базі даних
MySQL.

## Можливості

Для кожної сутності (студенти, тренери, секції, змагання, графік занять)
доступний повний набір операцій: перегляд усіх записів, додавання, редагування
та видалення. Окремо передбачено:

- запис студента до секції та видалення з неї;
- реєстрацію студента на змагання та внесення/оновлення результату;
- перегляд графіка роботи конкретної секції;
- перегляд секцій, якими керує тренер;
- пошук сутностей за (частковою) назвою/іменем.

## Архітектура

- `src/Types.hs` — типи даних для всіх сутностей.
- `src/Entity.hs` — класи `Entity` (перетворення в/з рядків MySQL, ім'я
  таблиці, стовпці, ідентифікатор) та `Searchable` (пошук за назвою), а також
  їхні інстанси для кожної сутності.
- `src/MySQLTypes.hs` — допоміжні функції конвертації між `MySQLValue` та
  звичайними типами Haskell (`Int`, `String`, `Day`, `TimeOfDay`).
- `src/DB.hs` — підключення до БД та універсальні/спеціалізовані SQL-запити
  (CRUD, вибірки з JOIN, пошук).
- `src/UI.hs` — консольне меню користувача.
- `app/Main.hs` — точка входу.

## Таблиці БД

Схема бази даних містить 7 таблиць:

| Таблиця               | Призначення                                   |
|------------------------|------------------------------------------------|
| `students`             | інформація про студентів                       |
| `coaches`               | інформація про тренерів                        |
| `sections`              | спортивні секції (кожна має тренера)           |
| `section_members`      | зв'язок студент — секція                       |
| `schedule`              | графік роботи секцій (день, час, місце)        |
| `competitions`          | план проведення змагань                        |
| `competition_members`   | учасники змагань та їхні результати            |

### Створення схеми

Застосунок сам створює всі таблиці при підключенні (`initSchema` у
`src/DB.hs`, виконується в `connectDB`) через `CREATE TABLE IF NOT EXISTS`,
тож вже наявні таблиці та дані не перезатираються. Вручну потрібно створити
лише саму базу даних — підключення націлене на конкретну БД і вона має
існувати заздалегідь:

```sql
CREATE DATABASE IF NOT EXISTS faculty_sport;
```

## Налаштування підключення

Застосунок читає пароль до БД зі змінної оточення `DB_PASSWORD`, яка
завантажується з файлу `.env` у корені проєкту:

```
DB_PASSWORD = "your_password"
```

Хост, порт, ім'я бази та користувача задано у `connectDB` (`src/DB.hs`):
`127.0.0.1:3306`, база `faculty_sport`, користувач `haskell_app`. За потреби
змініть ці значення під своє середовище.

## Збірка та запуск

Проєкт використовує [Stack](https://docs.haskellstack.org/):

```sh
stack build
stack exec lab1-faculty-sport-exe
```

Перед запуском переконайтеся, що MySQL-сервер запущено, база даних
`faculty_sport` створена, а файл `.env` містить правильний пароль. Таблиці
застосунок створить сам при першому підключенні.
